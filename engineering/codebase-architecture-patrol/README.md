# codebase-architecture-patrol：只读架构巡检

让 agent 定期巡检仓库架构健康度，找「浅模块 → 深模块」的深化机会，产出卡片式 markdown 报告。**只读评审：不改代码、不开 MR、不动仓库文档**，建议全部进报告，行动留给人。

## 它解决什么问题

让 AI「看看架构有什么问题」，最常见的跑偏不是看不出来，而是**看错东西、看错范围、看错形态**：

- **扫全仓库**：把三个月没动过的存量代码全翻一遍，报告被历史遗留淹没，和本周的工作毫无关系
- **报 bug 不报架构**：清单里全是 correctness 缺陷（空指针、SQL 写错），真正的深化机会一条没有
- **硬凑发现**：小仓库也要挤出十条「改进建议」，消耗的是报告的信任
- **建议落地形态缺失**：说「应该重构」却没有测试策略——改完之后旧单测是删是留、新接口怎么测，全靠猜
- **越界动手**：顺手把代码改了、把文档补了，评审变成了无人审批的变更

本技能把巡检收敛成一套硬纪律：范围只限**上周一 00:00 至上周日 24:00 合入 main 的提交**；每个候选必须过 **deletion test**（删掉该模块，复杂度是集中还是转移？只有集中才入围）；方案按**依赖四分类**定测试方式；上周无提交就如实报「无发现」。

## 使用

1. 把本目录复制到 agent 技能目录（如 `~/.hermes/skills/`），或按对应平台的技能加载机制配置
2. 对 agent 说「对 /path/to/repo 做一次架构巡检」即可；报告默认写到仓库外的临时目录，不污染工作区
3. 完整内容见 [SKILL.md](SKILL.md)

## 内容速览

- **范围纪律**：`git log --first-parent` 圈上周窗口，热点文件只从窗口内提交触碰的文件里选；存量问题只作背景一句，不单独立候选
- **深化机会判定**：五类摩擦信号（多模块跳转、接口≈实现、为可测试性抽纯函数、seam 泄漏、测不了）+ deletion test 门槛
- **依赖四分类 → 测试策略**：纯进程内 / 本地可替换 / 远程自有（port + 双 adapter）/ 真外部三方（mock）；接口即测试面，替换不叠加
- **seam 纪律**：一个 adapter 是假想 seam，两个才是真 seam；说不清第二个 adapter 是谁的 port 就是纯间接层
- **前端同等入围**：透传 props 包装组件、单薄 fetch hook、状态归属混放、层职责越界——规则以仓库自身声明为准，不臆造
- **报告形态**：每候选一卡片（文件 / 问题 / 方案 / 收益 / 推荐强度）+ Top recommendation；命名用仓库业务词汇，禁止「重构 XxxService」式空话
- **红旗表**：五条最常见的自我说服（扫全仓才彻底、bug 太明显必须报……）及对应现实

## 思想来源

深化分析框架（shallow/deep module、deletion test、seam 纪律、依赖四分类）参考自 [mattpocock/skills](https://github.com/mattpocock/skills) 的 `codebase-design` 与 `improve-codebase-architecture`，上溯 John Ousterhout《A Philosophy of Software Design》。本技能是定期巡检形态：无 grilling loop 与 HTML 报告，范围收窄为上周窗口。

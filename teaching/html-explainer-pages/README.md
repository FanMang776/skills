# html-explainer-pages（HTML 动画讲解页）

把一个概念、调研结论或流程做成**单文件、零依赖、滚动叙事的 HTML 动画页面**——
用户说「看字看不明白」「做个动画/图解/可视化讲一下」时的标准产出物。

## 核心思想

讲解页的难点从来不是视觉（那交给 `frontend-design` skill），而是三件事：

1. **叙事结构** —— 内容分屏，每屏只讲一件事：一句导语 + 一个可视化载体
2. **骨架模式** —— 全页面只用一种动效机制：元素默认隐藏，IntersectionObserver
   进入视口加 `.on` 类触发 CSS transition，触发即 `unobserve`（只演一次）
3. **验证流水线** —— 这是提速的大头。逐节 `scrollTo` → 截图 → DOM 断言，
   并且**截图空白 ≠ 页面坏**（预览窗合成器卡顿是常态，抖一下再截）

## 可视化载体（五种，覆盖 90% 场景）

| 载体 | 适用内容 |
|---|---|
| 代码/YAML 块 + 侧栏 hover 联动 | 讲一个配置、报文、定义的结构 |
| Tab 切换 | 同层级互斥的几个概念 |
| 左右映射动画 | 「A 怎么对应 B」的一切场景（列映射、翻译、协议对照） |
| 按钮驱动的步骤链 | 有先后顺序的过程（审批流、握手、生命周期） |
| 时间线 | 版本演进、历史脉络 |

Hero 只花一次大胆（图谱生长或首屏主动画），其余全克制。

## 使用

1. 触发：对 agent 说「把 X 做成动画讲解页 / 图解 / 可视化」
2. 按 [`SKILL.md`](SKILL.md) 的 5 步流程执行
3. 以 [`example-http-explainer.html`](example-http-explainer.html)
   （「一个 HTTP 请求的一生」）为底稿换内容，比从零写快一半以上；
   该示例五种载体齐备，交互全部实测通过
4. 视觉主题**默认浅色**（用户偏好），深色需用户先提出

## 关键纪律（实证踩过的坑）

- **先 DOM 断言，后改代码** —— 预览窗截图空白/超时先 `elementFromPoint` 验内容，
  内容在就是渲染卡顿，抖动重试；把卡顿当 bug 反复改代码是最贵的错误
- **外网 URL 不能 attach 预览** —— 必须本地 `python -m http.server` 起服务
- **动态生成的内容注意 reveal 时机** —— JS 生成的行别带隐藏类，或确保父容器先 `.on`
- **零外部请求** —— 不引 CDN/webfont，离线双击就能开
- **动效一律包 `prefers-reduced-motion`** —— 可访问性底线
